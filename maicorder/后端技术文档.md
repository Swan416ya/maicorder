# 后端技术文档

## 1. 项目概述

Maicorder 后端系统是一个基于 Spring Boot 的 RESTful API 服务，主要用于管理街机厅签到、游戏记录和用户认证等功能。系统采用分层架构，使用 MyBatis-Plus 作为 ORM 框架，JWT 进行无状态认证，为前端应用提供稳定的数据服务。

## 2. 技术栈

| 技术/框架 | 版本 | 用途 |
|---------|------|------|
| Spring Boot | - | 应用框架 |
| MyBatis-Plus | - | ORM 框架 |
| MySQL | - | 数据库 |
| JWT | - | 无状态认证 |
| Maven | - | 项目构建 |

## 4. 核心功能模块

### 4.1 用户认证模块

用户认证模块负责用户的登录、注册和身份验证，使用 JWT 进行无状态认证，确保 API 访问的安全性。

**主要功能：**
- 用户登录：验证用户名和密码，生成 JWT Token
- 用户注册：创建新用户，加密存储密码

**认证流程：**
1. 用户发送登录请求，携带用户名和密码
2. 后端验证用户名和密码是否正确
3. 验证通过后，生成 JWT Token 并返回给前端
4. 前端后续请求携带 Token 进行身份验证

### 4.2 签到管理模块

签到管理模块是系统的核心功能，负责用户在街机厅的签到记录、费用管理和游戏记录。

**主要功能：**
- 创建签到记录：记录用户在机厅的签到信息，包括机厅ID、用户ID、费用等
- 管理游戏场次：记录用户在签到期间玩的游戏场次
- 管理战绩：记录用户在每个游戏场次中的具体战绩

**签到流程：**
1. 用户选择机厅进行签到
2. 填写签到信息，包括费用、游戏场次和战绩
3. 后端验证数据并保存到数据库
4. 返回签到结果给前端

### 4.3 机厅管理模块

机厅管理模块负责机厅信息的管理，包括机厅的基本信息、位置等。

**主要功能：**
- 获取机厅列表：获取所有机厅的信息
- 创建机厅：添加新的机厅信息

## 5. API 接口文档

### 5.1 用户相关接口

#### 5.1.1 登录接口

**接口介绍：** 用于用户身份验证。校验用户名与密码后，生成 JWT Token 并返回用户基本信息（id、username、email），前端可将 Token 存入本地并在后续请求头中携带，用于访问需登录的接口。

**接口路径：** `POST /api/login`

**请求参数：**
```json
{
  "username": "string",  // 用户名
  "password": "string"   // 密码
}
```

**响应参数：**
```json
{
  "code": 200,           // 响应码
  "message": "操作成功",  // 响应信息
  "data": {
    "token": "string",   // JWT Token
    "user": {
      "id": 1,           // 用户ID
      "username": "string", // 用户名
      "email": "string"    // 邮箱
    }
  }
}
```

**错误响应：**
- 400: 用户名或密码不能为空
- 401: 用户名不存在或密码错误

#### 5.1.2 注册接口

**接口介绍：** 用于新用户注册。接收用户名、密码与邮箱，校验后对密码进行加盐 MD5 加密并落库，成功后即可使用该账号登录。

**接口路径：** `POST /api/register`

**请求参数：**
```json
{
  "username": "string",  // 用户名
  "password": "string",  // 密码
  "email": "string"      // 邮箱
}
```

**响应参数：**
```json
{
  "code": 200,           // 响应码
  "message": "操作成功",  // 响应信息
  "data": null
}
```

**错误响应：**
- 400: 用户名或密码不能为空
- 400: 用户名已存在

#### 5.1.3 获取 API Key

**接口介绍：** 用于个人中心展示或第三方调用时获取当前用户的 API Key。需在请求头中携带有效 JWT Token，后端根据 Token 解析出用户 ID 并返回该用户的 API Key。

**接口路径：** `GET /api/get-apikey`

**请求头：**
- `Authorization: Bearer <token>`（必填，登录后获得的 JWT）

**请求参数：** 无

**响应参数：**
```json
{
  "code": 200,
  "message": "操作成功",
  "data": "用户的 API Key 字符串"
}
```

**错误响应：**
- 401/402: 用户未登录
- 404: 用户不存在
- 400: API Key 未设置
- 500: 获取失败

#### 5.1.4 更新用户信息

**接口介绍：** 用于修改当前登录用户的资料（如用户名、邮箱等）。请求体为键值对，仅会更新传入的字段；需在请求头中携带有效 JWT Token。

**接口路径：** `POST /api/update-user`

**请求头：**
- `Authorization: Bearer <token>`（必填）
- `Content-Type: application/json`

**请求参数：**
```json
{
  "username": "string",  // 可选，新用户名
  "email": "string"      // 可选，新邮箱
}
```

**响应参数：**
```json
{
  "code": 200,
  "message": "操作成功",
  "data": { "更新后的用户信息字段" }
}
```

**错误响应：**
- 401/402: 用户未登录
- 400: 参数错误
- 500: 更新失败

### 5.2 签到相关接口

#### 5.2.1 创建签到记录

**接口介绍：** 用于在机厅打卡，一次提交完成整条签到及下属游戏场次、战绩的创建。必填机厅 ID、用户 ID、签到日期；费用与备注可选；若包含游戏场次，则每个场次下至少需有一条战绩。

**接口路径：** `POST /api/checkins`

**请求参数：**
```json
{
  "arcadeId": 1,         // 机厅ID
  "userId": 1,           // 用户ID
  "cost": {
    "coin": 50.0,        // 币费
    "food": 20.0,        // 餐费
    "water": 5.0,        // 水费
    "transport": 10.0    // 交通费
  },
  "comment": "今天玩得很开心", // 备注
  "checkInDate": "2024-01-01", // 签到日期
  "gameSessions": [      // 游戏场次
    {
      "gameType": "Dance Dance Revolution", // 游戏类型
      "currentRating": "AAA",                // 当前评级
      "pcCount": 2,                          // PC数
      "records": [                           // 战绩
        {
          "songName": "Butterfly",          // 歌曲名
          "score": "100.00%",               // 分数
          "clearStatus": "FC"               // 通关状态
        }
      ]
    }
  ]
}
```

**响应参数：**
```json
{
  "code": 200,           // 响应码
  "message": "操作成功",  // 响应信息
  "data": {
    "id": 1,             // 签到ID
    "arcadeId": 1,       // 机厅ID
    "userId": 1,         // 用户ID
    "coinCost": 50.0,    // 币费
    "foodCost": 20.0,    // 餐费
    "waterCost": 5.0,    // 水费
    "transportCost": 10.0, // 交通费
    "comment": "今天玩得很开心", // 备注
    "checkInTime": "2024-01-01" // 签到时间
  }
}
```

**错误响应：**
- 400: 机厅ID不能为空
- 400: 机厅ID必须为有效数字
- 400: 用户ID不能为空
- 400: 日期格式错误，需为yyyy-MM-dd
- 400: 游戏场次[游戏类型]至少添加一条战绩
- 400: 请至少添加一个游戏场次记录
- 500: 签到记录插入失败
- 500: 游戏场次插入失败
- 500: 战绩插入失败

#### 5.2.2 获取用户签到记录列表

**接口介绍：** 根据用户 ID 查询该用户全部签到记录，按签到时间倒序返回。用于履历页、日历等展示列表，不包含游戏场次与战绩详情，需详情时可再调「获取签到记录详情」接口。

**接口路径：** `GET /api/records/checkins/{userId}`

**路径参数：**
- `userId`：用户 ID（Long）

**请求参数：** 无

**响应参数：**
```json
{
  "code": 200,
  "message": "操作成功",
  "data": [
    {
      "id": 1,
      "arcadeId": 1,
      "userId": 1,
      "coinCost": 50.0,
      "foodCost": 20.0,
      "waterCost": 5.0,
      "transportCost": 10.0,
      "comment": "备注",
      "checkInTime": "2024-01-01"
    }
  ]
}
```

#### 5.2.3 获取签到记录详情

**接口介绍：** 根据签到记录 ID 查询单条签到的完整信息，包含关联的游戏场次及每个场次下的战绩列表。用于记录详情页展示单次出勤的完整数据。

**接口路径：** `GET /api/records/checkins/detail/{checkInId}`

**路径参数：**
- `checkInId`：签到记录 ID（Long）

**请求参数：** 无

**响应参数：**
```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "checkIn": { "签到记录对象" },
    "gameSessions": [
      {
        "id": 1,
        "checkInId": 1,
        "gameName": "MAIMAI_DX",
        "pcCount": 2,
        "currentRating": "14.5",
        "records": [
          { "songName": "曲名", "score": "98.5%", "clearStatus": "FC" }
        ]
      }
    ]
  }
}
```

**错误响应：**
- 404: 签到记录不存在
- 500: 获取详情失败

#### 5.2.4 按日期范围获取签到记录

**接口介绍：** 根据用户 ID 与起止日期查询该时间范围内的签到记录列表，按签到时间倒序。适用于按日历或时间段筛选履历。

**接口路径：** `GET /api/records/checkins/date/{userId}`

**路径参数：**
- `userId`：用户 ID（Long）

**请求参数（Query）：**
- `startDate`：开始日期，格式 `yyyy-MM-dd`
- `endDate`：结束日期，格式 `yyyy-MM-dd`

**响应参数：** 与「获取用户签到记录列表」的 `data` 结构一致。

#### 5.2.5 分页获取签到记录

**接口介绍：** 按分页方式获取指定用户的签到记录，返回当前页数据及总条数、总页数等，适用于履历列表分页加载。

**接口路径：** `GET /api/records/checkins/page/{userId}`

**路径参数：**
- `userId`：用户 ID（Long）

**请求参数（Query）：**
- `page`：当前页码，默认 1
- `size`：每页条数，默认 10

**响应参数：**
```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "records": [ "当前页签到记录数组" ],
    "total": 100,
    "current": 1,
    "size": 10,
    "pages": 10
  }
}
```

#### 5.2.6 获取用户战绩统计

**接口介绍：** 按用户 ID 汇总该用户的签到次数、游戏场次数量、战绩数量等统计信息，可用于个人主页或数据概览。

**接口路径：** `GET /api/records/stats/{userId}`

**路径参数：**
- `userId`：用户 ID（Long）

**请求参数：** 无

**响应参数：**
```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "checkInCount": 10,
    "sessionCount": 25,
    "recordCount": 80
  }
}
```

**接口介绍：** 新增一条机厅信息（通过请求体提交）。名称、地址、经纬度及省市区等均可选填，保存后返回带自增 ID 的机厅对象，供后续签到选择使用。

**请求参数：**

**响应参数：**
```json
{

  "data": {
    "id": 1,             // 机厅ID
```

**接口介绍：** 根据机厅 ID 列表批量查询机厅名称，返回 ID 与名称的映射。用于在签到列表、记录详情等场景中批量展示机厅名称，避免逐条请求。

**接口路径：** `POST /api/arcades/names`

**请求参数：**
```json
[ 1, 2, 3 ]
```
（请求体为机厅 ID 数组，Long 类型）

**响应参数：**
```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "1": "机厅A",
    "2": "机厅B",
    "3": "机厅C"
  }
}
```
（`data` 为 ID → 名称的键值对）

#### 5.3.4 添加机厅（独立接口）

**接口介绍：** 与「创建机厅」功能类似，用于新增机厅。路径为 `/add-arcade`，请求体为机厅对象，插入后返回带 ID 的机厅信息。前端可根据需要调用本接口或 `POST /api/arcades`。

**接口路径：** `POST /api/arcades/add-arcade`

**请求参数：** 与 5.3.2 创建机厅 相同（JSON 机厅对象）

**响应参数：** 与 5.3.2 创建机厅 相同（返回带 `id` 的机厅对象）

**错误响应：**
- 500: 添加机厅失败

#### 10.2.2 数据库表结构初始化

执行以下 SQL 脚本创建所需的表结构：

```sql
-- 用户表
CREATE TABLE `sys_user` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '用户ID',
  `username` VARCHAR(50) NOT NULL COMMENT '用户名',
  `password` VARCHAR(100) NOT NULL COMMENT '密码（MD5加密）',

-- 机厅表
CREATE TABLE `arcade` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '机厅ID',
  `name` VARCHAR(100) NOT NULL COMMENT '机厅名称',
  `address` VARCHAR(255) COMMENT '机厅地址',
  `latitude` DOUBLE COMMENT '纬度',
  `longitude` DOUBLE COMMENT '经度',
  `province` VARCHAR(50) COMMENT '省份',
  `city` VARCHAR(50) COMMENT '城市',
  `district` VARCHAR(50) COMMENT '区县',
  PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='机厅表';

-- 签到表
CREATE TABLE `check_in` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '签到ID',
  `arcade_id` BIGINT NOT NULL COMMENT '机厅ID',
  `user_id` BIGINT NOT NULL COMMENT '用户ID',
  `coin_cost` DOUBLE DEFAULT 0 COMMENT '币费',
  `food_cost` DOUBLE DEFAULT 0 COMMENT '餐费',
  `water_cost` DOUBLE DEFAULT 0 COMMENT '水费',
  `transport_cost` DOUBLE DEFAULT 0 COMMENT '交通费',
  `comment` VARCHAR(255) COMMENT '备注',
  `check_in_time` DATE NOT NULL COMMENT '签到时间',
  PRIMARY KEY (`id`),
  KEY `idx_user_id` (`user_id`),
  KEY `idx_arcade_id` (`arcade_id`),
  KEY `idx_check_in_time` (`check_in_time`),
  CONSTRAINT `fk_check_in_arcade` FOREIGN KEY (`arcade_id`) REFERENCES `arcade` (`id`) ON DELETE CASCADE,
  CONSTRAINT `fk_check_in_user` FOREIGN KEY (`user_id`) REFERENCES `sys_user` (`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='签到表';

-- 游戏场次表
CREATE TABLE `game_session` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '场次ID',
  `check_in_id` BIGINT NOT NULL COMMENT '签到ID',
  `game_name` VARCHAR(50) NOT NULL COMMENT '游戏名称',
  `pc_count` INT DEFAULT 0 COMMENT 'PC数',
  `current_rating` VARCHAR(50) COMMENT '当前评级',
  PRIMARY KEY (`id`),
  KEY `idx_check_in_id` (`check_in_id`),
  CONSTRAINT `fk_game_session_check_in` FOREIGN KEY (`check_in_id`) REFERENCES `check_in` (`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='游戏场次表';

-- 战绩表
CREATE TABLE `play_record` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '战绩ID',
  `game_session_id` BIGINT NOT NULL COMMENT '游戏场次ID',
  `song_name` VARCHAR(100) NOT NULL COMMENT '歌曲名',
  `difficulty` VARCHAR(20) COMMENT '难度',
  `score` VARCHAR(20) COMMENT '分数',

) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='战绩表';
```

#### 10.2.3 索引与外键配置

**索引配置：**
- `sys_user` 表：为 `username` 字段创建唯一索引，加速用户名查询
- `check_in` 表：为 `user_id`、`arcade_id` 和 `check_in_time` 字段创建索引，加速签到记录查询
- `game_session` 表：为 `check_in_id` 字段创建索引，加速游戏场次查询
- `play_record` 表：为 `game_session_id` 字段创建索引，加速战绩查询

**外键配置：**
- `check_in` 表引用 `arcade` 表和 `sys_user` 表
- `game_session` 表引用 `check_in` 表
- `play_record` 表引用 `game_session` 表
- 所有外键均设置为 `ON DELETE CASCADE`，确保数据一致性

#### 10.2.4 数据库优化建议

1. **定期备份**

3. **安全配置**

   - 创建专用数据库用户并授予最小必要权限：
     ```sql
     CREATE USER 'maicorder'@'localhost' IDENTIFIED BY 'your_secure_password';

     FLUSH PRIVILEGES;
     ```
   - 然后修改 `application.properties` 中的数据库连接配置
